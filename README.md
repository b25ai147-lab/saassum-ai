# ✉️ SaaSsum AI: Lightweight AI Agent for Email Insights

> Hackathon problem: *"Create a lightweight AI agent that summarizes Gmail/email messages into actionable insights."*

Paste an email (subject, sender, body), or pick one from your Gmail inbox, and get:

1. A concise **summary**
2. **Tasks** with the **responsible person** and **deadline**
3. **Important dates**
4. **Priority** (High / Medium / Low) with an **explanation**
5. A **suggested reply** (subject + body)

Built with **Java 17 + Spring Boot** (backend) and **HTML, CSS & vanilla JavaScript** (frontend).

## Demo output vs. real AI output

Every response carries a `source` field and the UI shows a banner, so judges can always tell which one they are looking at.

| Mode | Banner in the UI | API key? | How it works |
|------|------------------|----------|--------------|
| **Demo** (default) | 🧪 *DEMO OUTPUT: not generated by an AI model* | No | Rule-based engine: sentence scoring, keyword cues, name and date detection. No AI model is involved. |
| **AI** (optional) | ✨ *AI-GENERATED RESULT* + model name | Yes | The Java backend calls an OpenAI-compatible chat API. The key stays on the server. |

If AI mode is on but fails (no key, network error, bad response), the app falls back to the demo engine and says so in a blue notice. It never presents demo results as AI.

## Gmail integration (optional)

- Uses the **OAuth 2.0 authorization-code flow**, read-only scope `gmail.readonly`.
- No Google SDK: the backend talks to Google's HTTPS endpoints directly.
- Client secret and access token stay on the server (token lives in the in-memory HTTP session). A random `state` value protects the callback.
- Nothing is stored on disk. Sessions expire after 30 minutes and tokens after about an hour.
- **Without Gmail configured the app works fully with pasted emails**, and the Gmail panel simply shows "Not configured".

### Gmail setup (about 10 minutes)

1. Go to <https://console.cloud.google.com/> and create a project.
2. **APIs & Services → Library →** enable **Gmail API**.
3. **APIs & Services → OAuth consent screen:** choose **External**, fill in the app name and your email, and add the scope `.../auth/gmail.readonly`. Keep the app in **Testing** mode and add your own Gmail address under **Test users**.
4. **APIs & Services → Credentials → Create credentials → OAuth client ID → Web application.**
   Add this **Authorized redirect URI** exactly: `http://localhost:8080/api/gmail/callback`
5. Copy the **Client ID** and **Client secret** into `config/local.properties` (see below) or into the environment variables `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`.
6. Restart the app and click **Connect Gmail**. Google will show an "unverified app" warning while the app is in Testing mode. That is expected: choose **Continue**.

> `gmail.readonly` is a *restricted* scope. For a hackathon, Testing mode with test users is enough. Public release would require Google's verification process.

## Requirements

- JDK 17 or newer

## Run it

### IntelliJ IDEA
1. **File → Open** and select the `saassum-ai` folder (the one containing `pom.xml`).
2. Wait for Maven to import dependencies. Set the Project SDK to JDK 17+ if asked.
3. Open `SaaSsumApplication.java` and click the green ▶ next to `main`.
4. Open <http://localhost:8080>

### VS Code
1. Install the **Extension Pack for Java** and the **Spring Boot Extension Pack**.
2. **File → Open Folder** and select `saassum-ai`.
3. Open `SaaSsumApplication.java` and click **Run** above `main` (or use the Spring Boot Dashboard).
4. Open <http://localhost:8080>

### Command line
```bash
mvn spring-boot:run
```

## Optional configuration

Copy `config/local.properties.example` to `config/local.properties` (this file is git-ignored) and fill in only what you need:

- **AI:** `saassum.mode=ai` and `saassum.ai.api-key=...` (any OpenAI-compatible API; change `saassum.ai.base-url` and `saassum.ai.model` for other providers).
- **Gmail:** `saassum.google.client-id` and `saassum.google.client-secret`.

Or use environment variables: `SAASSUM_MODE`, `AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`.

Delete any placeholder lines you are not using, so that `PASTE_..._HERE` values are never read as real keys.

## REST API

| Method | Path | Description |
|--------|------|-------------|
| POST | `/api/analyze` | Body: `{"subject","sender","body"}` (only `body` is required). Returns the analysis. |
| GET | `/api/sample` | A sample email. |
| GET | `/api/status` | Active engine (`demo` or `ai`). |
| GET | `/api/gmail/status` | `{configured, connected, email}` |
| GET | `/api/gmail/login` | Starts Google sign-in (browser redirect). |
| GET | `/api/gmail/callback` | OAuth redirect target. |
| GET | `/api/gmail/messages` | Latest 10 inbox messages. |
| GET | `/api/gmail/messages/{id}` | One message (subject, sender, body). |
| POST | `/api/gmail/logout` | Forget the Gmail connection. |

```bash
curl -X POST http://localhost:8080/api/analyze \
  -H "Content-Type: application/json" \
  -d '{"subject":"Invoice","sender":"Sam <sam@example.com>","body":"Hi, please send the invoice by Friday 3 PM. Thanks!"}'
```

Validation error example (HTTP 400):
```json
{"error": "Please paste the email body before clicking Analyze."}
```

## Security

- AI keys, the Google client secret and access tokens are read and held only by the backend.
- `config/local.properties`, `.env` and `client_secret*.json` are in `.gitignore`.
- The frontend renders results with `textContent`, so pasted HTML cannot run scripts.
- The AI prompt treats the email as untrusted data.
- The Gmail scope is read-only. The app can never send, delete or modify mail.
- If you ever commit a key by mistake, revoke it at the provider immediately.

## Limitations

- The demo engine is heuristic: owner detection looks for capitalised names followed by words like "will" or "please", and it only understands English.
- Gmail access works in Google's Testing mode for listed test users only.
- Only the 10 most recent inbox messages are listed.
